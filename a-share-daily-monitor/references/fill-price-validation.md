# 条件单成交价验证 — 先核实再更新成本

## 触发场景

用户报告「XX条件单触发了，买了X股在Y.YY元」

## 核心原则

**不要直接接受用户报的触发价作为成本更新依据。** 条件单的触发价和实际成交价可能不同：
- 条件单在Y.YY触发后，实际成交可能按当时盘口卖一价执行
- 如果触发后价格继续下探，成交价可能低于触发价
- 如果触发后价格反弹，成交价可能接近触发价

## 验证流程

### 第1步：拉当天实时行情，确认日内最低价

```python
curl -s "https://hq.sinajs.cn/list=<code>" \
  -H "Referer: https://finance.sina.com.cn" | iconv -f gbk -t utf-8
# 解析第5字段 = 当日最低价
```

### 第2步：对比触发价 vs 日内最低价

| 对比结果 | 含义 | 动作 |
|:--------|:----|:-----|
| 触发价 = 日内最低价（接近） | 成交在最低点附近 | 接受用户价格，更新成本 |
| 触发价 > 日内最低价 | 可能有更好的成交价 | 提示用户，确认实际成交价后再更新 |
| 触发价 < 日内最低价 | 不可能（数据异常） | 重新拉数据核实 |

### 第3步：询问用户实际成交价

如果日内最低价明显低于触发价（如触发1.171，最低1.164），**先问用户实际成交价再更新成本**：

```
今天该标的日内最低是X.XXXX（低于你的触发价），
你账户里实际成交价是多少？
```

### 第4步：更新成本

只有拿到**实际成交价**后才能更新：
- 脚本COST_PRICE
- memory持仓记录
- cost-records.md

## 实战案例：2026-07-06 AI ETF(515980)

- 用户报告：条件单触发买入3000股@1.171
- 新浪实时数据验证：当日最低价1.164，低于触发价0.6%
- 用户质疑「不是今天最低价」
- 正确做法：先确认实际成交价再更新成本，而非直接1.171×3000
