> **说明**  
> - 下列报告由本仓库脚本对 **`portfolio.example.json`** 实跑生成（腾讯/新浪行情 + AKShare 净值）。  
> - 标的名称是「示例-*」，成本/峰值为演示值，**不是**任何人的真实持仓。  
> - 截取自交易日 **2026-09-10** 收盘后复跑（时间戳可能显示晚间，价格为当日收盘）。  
> - 不构成投资建议；仅展示 Agent 应如何把「脚本输出 → 能不能买」串起来。

复现命令（在 `a-share-daily-monitor` 下）：

```bash
python3 scripts/morning_check.py
python3 scripts/pre_close_check.py
python3 scripts/daily_monitor.py
# 或：bash ../scripts/capture_example_run.sh
```

## 场景

**用户：** 今天震荡，帮我按示例组合跑早盘、尾盘和日报。芯片跌破均线了，想加一点，行不行？

**Agent 应做的事：**

1. 跑监控脚本，把完整报告贴进对话（不要只口头摘要）。  
2. 加载 `family-wealth-ips`：先问「哪笔钱 / 应急金 / 股票会不会买太多」。  
3. 结合脚本信号给白话结论：`能不能买: 可以 / 先少买点 / 先别买`。

**关于旧版「主力资金信号 / 暂不可用」：**  
当时整段是因为东方财富 `fund_etf_fund_daily_em` 超时/断连。  
标题也有误导：免费源是 **市价 vs 净值折溢价**，不是「主力净流入」。典型输出：

```
三、折溢价对照（市价 vs 净值）
  净值日期: 2026-09-10
  示例-AI ETF        市价:0.9880  NAV:0.9994  折溢价:-1.14%
  示例-芯片ETF         市价:1.0120  NAV:1.0374  折溢价:-2.45%
```

**读表注意（真实坑）：**

| 列 | 含义 |
|----|------|
| 成本盈亏 | 相对 `portfolio` 里的 cost（示例组合小幅浮盈） |
| 距峰值 / 止盈 | 相对配置的 `peak`（示例约 -4%） |
| 回撤峰值（日报） | 相对 **近 60 日净值最高点**，可远大于配置 peak；信号「深回撤」是技术提示，不等于已触发止盈规则 |

两市成交额 **1.65 万亿** 来自实时指数字段（`[来源:realtime]`），不是 `volume×均价` 瞎估。

## 4）串上「能不能买」（示例回答）

假设用户补充：这是自己炒股的钱，应急金约 8 个月，股票类约 22%，上限 30%。

```
能不能买: 先少买点（或不加）
这是哪笔钱: 自己炒股的钱
应急金: 约 8 个月 ✓
股票类仓位: 约 22% / 上限 30%，空间有，但今天不是进攻日

依据（来自上面实跑）:
- 上证/科创小跌，两市成交 1.65 万亿偏冷（黄灯）
- 芯片破 20MA，相对配置峰值仅约 -4%，未到止盈线，但也没有放量企稳信号
- 早盘/尾盘均无红色硬警报；军工只是「过成本 → 重新评估」

建议:
- 默认: 先别加芯片；若一定要做，用原计划仓位的 1/3～1/2 试仓，并写清止损/回补条件
- 观察仓军工: 过成本不等于该加，先问这仓还要不要留
```

## 5）反例

- 只根据「回撤峰值 34%」就喊「必须减一半」→ 错（应先看配置 peak / 规则是否触发）。  
- 未问哪笔钱，直接给加仓清单 → 错。  
- 把 example 组合成本当成用户真实成本 → 错。
