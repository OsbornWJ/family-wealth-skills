# 盘中分析 响应模板

当用户说"盘中分析"时，必须拉取实时数据并直接输出完整格式化报告。

## 必须拉取的数据

1. 大盘指数（上证/科创50/深证）— 新浪实时
2. 全持仓实时价（5只ETF + 建行 + 券商512880）— 新浪实时
3. 关键位偏离（峰值/成本/MA60/临界）— 计算
4. 午后 vs 盘中高点对比（判断是否跳水）
5. 创新药浮亏 vs 硬止损线
6. 券商入场状态（vs MA60）

## 输出格式

必须包含：
- 一、大盘（指数 + 涨跌幅）
- 二、持仓实时（表格：标的/现价/涨跌/关键位偏离）
- 三、重点信号（芯片峰值突破、创新药浮亏预警、券商入场状态等）
- 四、午后关注（有无跳水风险/和上周四对比）

## 铁律

- 所有数据必须在回复中完整展示，不得只说"数据拉好了"
- 使用新浪实时接口 + time.sleep(0.3) 防限流
- 创新药浮亏用百分比明确标注，并显示距硬止损线距离
- 和上一个交易日同时间对比（"上周四此时"模式）
- **⚡ 区分已建仓 vs 观察中标的**：券商ETF(512880)、军工ETF(512660)是"观察/待建仓"非实际持仓，输出时不可计算成本/浮盈。只显示实时价+涨跌幅。对照监控标的表确认建仓状态后再输出。
- **⚡ 大反弹日（科创50/芯片/AI >5%）走场景J，不走此通用模板** — 反弹日的分析框架与急跌日完全不同，核心是「不追高+检查条件单距离」而非「恐慌检查+补仓」
- **⚡ 仓位权重语境化（Percent-in-context 规则）**：
  - 当报告某个持仓标的大涨/大跌时，必须同时输出：(1)该标的占总资产百分比；(2)该标的当日贡献的总资产涨跌幅（= 仓位权重 × 标的涨跌幅）
  - 示例："创新药+10.87%，但仅占总资产5.2%，对总账户贡献+0.5%"
  - 原理：高百分比涨幅在轻仓上意义有限，低百分比跌幅在重仓上杀伤力大。不让用户被数字吓到或误导。
  - **这项规则比记忆更优先**——不是风格偏好，是分析客观性的根本要求。
